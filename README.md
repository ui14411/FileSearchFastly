# FileSearchFastly

> 基于 Qt 6 + C++ 的 Windows 全盘文件搜索工具

支持 NTFS/USN 快速枚举（管理员模式）、目录遍历兜底、SQLite 全量索引、多线程扫描与无限滚动加载。

---

## 功能特性

- **全盘搜索**：自动检测所有磁盘（C/D/E/F...），支持 NTFS 与移动盘（FAT/exFAT）
- **三种搜索模式**：文件名模糊搜索 / 后缀精确过滤 / 全量浏览
- **USN 加速**（管理员运行）：NTFS 卷通过 USN 日志秒级枚举变更（增量模式）
- **目录遍历兜底**：无法使用 USN 时（非管理员 / FAT/exFAT / USN 不可用）自动降级为完整目录遍历
- **移动盘数据完整**：U 盘（FAT/exFAT 无 USN 日志）每次启动全量遍历重建，程序关闭期间的变更不会漏
- **多线程扫描**：多磁盘并行遍历 + 背压控制，内存可控
- **SQLite 索引**：针对 239 万条文件记录进行测试，后缀过滤约 1ms，文件名 LIKE 查询约 115ms
- **无限滚动**：500 条/批懒加载，首屏自动补载，不卡 UI
- **双击定位**：双击结果自动打开资源管理器并选中文件
- **垂直滚动条**：自定义样式，支持拖拽
- **增量更新**：NTFS 盘 dirty 检测 + 移动盘 12 小时兜底重建

## 使用说明

### 运行环境

- Windows 10/11（64 位）
- 建议以**管理员身份运行**（启用 USN 加速 + 完整 NTFS 权限）

### 基本操作

1. 启动后自动扫描全部磁盘（首次全量遍历约 30-50 分钟，视磁盘容量）
2. 顶部输入关键词 → 选择模式 → 回车/点击搜索
3. 双击结果 → 资源管理器定位

### 三种模式

| 模式 | 说明 |
|------|------|
| 文件名搜索 | 按关键词模糊匹配文件名 |
| 文件后缀 | 精确匹配后缀（如 `file` 只显示 `.file` 文件）|
| 全部文件 | 浏览全部分区索引 |

### 日志

- 日志文件：**`scan.log`**（与 exe 同级目录）
- 记录：启动/退出、扫描进度、USN 枚举统计、错误信息
- Release 下调试输出（qDebug）默认不写日志，错误统一走 qWarning 落盘

## 技术架构

```
┌─────────────┐     ┌──────────────┐     ┌─────────────┐
│  main.qml   │ ──► │ FileInteract │ ──► │ FileScanner │
│  (UI/前端)  │     │ (QML 桥接)   │     │ (扫描调度)  │
└─────────────┘     └──────────────┘     └──────┬──────┘
                                                 │
                                ┌────────────────┼────────────────┐
                                ▼                ▼                ▼
                        ┌─────────────┐  ┌─────────────┐  ┌─────────────┐
                        │ DriveScanner│  │  增量/USN   │  │ FileDatabase│
                        │ (盘级遍历)  │  │ (dirty/12h) │  │ (SQLite)    │
                        └─────────────┘  └─────────────┘  └──────┬──────┘
                                                                  │ dbThread
                                                          ┌───────▼────────┐
                                                          │ fileindex.db   │
                                                          └────────────────┘
```

### 线程模型

- **UI 线程**：QML 渲染、结果展示（500 条/批懒加载）
- **扫描线程**：每盘一个遍历线程，多盘并行
- **dbThread**：SQLite 写库串行队列（事务批量插入，防锁冲突）
- **线程池**：搜索结果 QVariantMap 转换、排序（不卡 UI）
- **背压**：内存中待写批次达到阈值（30 批）时暂停扫描，防止 OOM

### 性能数据（实测）

| 项目 | 数值 |
|------|------|
| 全量目录遍历（首次建库）| 约 53 分钟 / 238.8 万条 / ~740 条每秒 |
| USN 枚举（NTFS，秒级）| 135 万条 / 秒级（增量模式可用）|
| 后缀过滤查询 | ~1ms |
| 文件名 LIKE 查询 | ~115ms（239 万条全表）|
| 结果分批加载 | 500 条/批 |

### 数据库

- 表：`files`（path/name/suffix/size/modified_time/is_folder）
- 索引：`idx_suffix` / `idx_name`
- WAL 模式 + 自动 checkpoint，扫描与搜索并发读
- metadata 表：记录 initial_scan、dirty 标记、最后遍历时间

## 已知限制

1. **USN 全量枚举未打通**：FSCTL_ENUM_USN_DATA 记录无 Parent 字段，无法回溯完整路径；$MFT 直读被系统拒绝（err=5，需驱动级权限）。当前 USN 仅用于**增量**，全量依赖目录遍历
2. **移动盘（FAT/exFAT）**：无 USN 日志 → 程序关闭期间变更无法增量检测 → 每次启动全量重建（保证数据完整，代价是启动扫描较慢）
3. **搜索与扫描并发**：扫描写库与搜索请求共用 dbThread 队列，扫描中发起搜索会排队等待（扫描完成后恢复秒级响应）

## 构建

### 环境

- Windows 10/11 64 位
- Qt 6.7.3
- MSVC 2022
- CMake
- Windows SDK

### 编译

使用 Qt Creator 或 Visual Studio 打开项目并配置 Qt 6.7.3 MSVC 2022 64-bit Kit。

也可以使用 CMake：

```bat
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
```

### 部署

- Qt 6 DLL 需随 exe 分发（windeployqt）
- manifest 已嵌入（requireAdministrator，自动请求管理员权限）
